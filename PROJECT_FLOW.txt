2. SECURITY / REQUEST GATEWAY
-------------------------------------------------------------------------------
[DONE] `/api` prefix for every backend route (src/routes/api/index.ts)
[DONE] X-API-Key header guard on every /api/* route (src/plugins/api-key-guard.ts)
       - Timing-safe comparison against API_KEY env var
[DONE] JWT auth (src/plugins/jwt.ts, src/utils/token.ts)
       - Tokens are NON-EXPIRING by design (no `exp` claim, expiresAt: null)
       - `app.authenticate` preHandler decorator verifies the token and
         populates request.user = { userId, role }
[DONE] Role-based access control - coarse tier (src/middleware/rbac.ts)
       - `requireRole(...roles)` preHandler restricts a route to specific roles
[DONE] Role-based access control - fine-grained tier (inside each *.service.ts)
       - e.g. "HR can only manage Employee records", "cannot delete own account"
[DONE] Per-user, per-endpoint permission system (src/middleware/permission-guard.ts)
       - `permissions` table: id, userId, path (route pattern e.g. /api/users/:id),
         method (GET/POST/PUT/PATCH/DELETE), status (ACTIVE/INACTIVE)
       - `checkPermission` middleware runs after app.authenticate: looks up an
         ACTIVE grant for (current user, route pattern, HTTP method); 403 if none
       - ADMIN role always bypasses this check (prevents total lockout)
       - Wired into users / roles / attendance / permissions routes

3. ARCHITECTURE PATTERN (used by every feature module below)
-------------------------------------------------------------------------------
    routes -> controller -> service -> validation (zod) -> repository -> DB

[DONE] Layered folder structure per feature: src/modules/<feature>/
           <feature>.routes.ts       (Fastify route registration + RBAC)
           <feature>.controller.ts   (parses request, calls service, sends response)
           <feature>.service.ts      (business rules / authorization logic)
           <feature>.validation.ts   (zod schemas for request bodies/queries)
       src/repositories/<feature>.repository.ts   (all direct Sequelize/DB calls)
[DONE] Scoped, per-layer logging (src/utils/scoped-logger.ts)
       - Every function logs with { layer: "<Name>Controller/Service/Repository",
         fn: "<functionName>" } so a single request can be traced end-to-end,
         e.g. [UserController] updateUserHandler -> [UserService] updateUser
         -> [UserRepository] save
[DONE] Standard success response envelope (src/utils/response.ts):
         { success: true, data: ... }
[DONE] Standard validation error envelope (src/utils/validation.ts) via zod
[DONE] Custom typed app errors (src/utils/app-error.ts):
         AppError / NotFoundError / ConflictError / ForbiddenError / BadRequestError

9. ATTENDANCE MANAGEMENT  (src/modules/attendance/)
-------------------------------------------------------------------------------
[DONE] Attendance model (src/models/attendance.model.ts)
       - One row per user per calendar date (unique userId+date)
       - status: PRESENT | ABSENT | HOLIDAY
       - checkInTime / checkOutTime / workingHours (auto-computed on checkout)
       - Attendance is tracked Monday-Friday only
[DONE] POST /api/attendance   - mark today's attendance (upsert, TODAY only)
       - status=PRESENT: first call records check-in, a later same-day call
         fills in check-out; working hours auto-calculated
       - status=ABSENT: employee can self-declare absent for today directly,
         no approval needed
       - Rejected outright for any date other than today, and on weekends
[DONE] GET  /api/attendance          - list attendance (Employee: own only,
       HR: Employees only, Admin: everyone) with pagination + filters
       (date, status, userId)
[DONE] GET  /api/attendance/:id      - get a single attendance record (scoped)
[DONE] No DELETE endpoint for attendance at all - history is never deletable
       through the API (audit trail integrity)

   -- Correction requests / "claims" for PAST dates -----------------------
[DONE] AttendanceCorrectionRequest model (src/models/attendance-correction-request.model.ts)
       - Separate table: userId, attendanceId (nullable), requestedDate,
         requestedDay, requestedStatus (PRESENT/ABSENT/HOLIDAY),
         requestedCheckInTime/CheckOutTime/WorkingHours, reason,
         status (PENDING/APPROVED/REJECTED), reviewedBy, reviewedAt, reviewNote
[DONE] POST /api/attendance/corrections           - raise a claim
       - requestedStatus=PRESENT: time-correction claim, past dates only
       - requestedStatus=ABSENT / HOLIDAY: can also target today
       - Nothing in the main `attendances` table changes yet - PENDING only
[DONE] GET  /api/attendance/corrections            - list claims (scoped by role)
[DONE] GET  /api/attendance/corrections/:id         - get one claim (scoped)
[DONE] PATCH /api/attendance/corrections/:id/review - approve/reject (Admin/HR only)
       - APPROVE is the ONLY code path that ever writes a past date into the
         `attendances` table - patches the existing row or creates a new
         backfilled one, using the claim's requestedStatus/times
       - REJECT leaves `attendances` untouched
       - HR may only review claims raised by Employees

10. CRON JOBS  (src/jobs/)
-------------------------------------------------------------------------------
[DONE] node-cron scheduler wired into server bootstrap/shutdown (src/jobs/index.ts)
       - startCronJobs() called after DB connects & server starts listening
       - stopCronJobs() called during graceful shutdown
       - ENABLE_CRON_JOBS env flag can disable both jobs entirely
[DONE] Job 1 - Attendance reminder (src/jobs/attendance-reminder.job.ts)
       - Runs 08:00, Monday-Friday (CRON_TIMEZONE env, default UTC)
       - Emails every active user who has NOT yet marked today's attendance,
         reminding them to log in and mark it
[DONE] Job 2 - Auto-absence marker (src/jobs/attendance-absence-marker.job.ts)
       - Runs 19:00, Monday-Friday
       - Any active user with NO attendance row at all for today is
         automatically marked ABSENT in the `attendances` table, then emailed
       - Users who already marked PRESENT / ABSENT / HOLIDAY are left alone
[DONE] Both jobs skip themselves entirely on weekends (belt-and-suspenders,
       on top of the Mon-Fri cron schedule)
[DONE] Email utility (src/utils/mailer.ts) - nodemailer wrapper
       - Best-effort send: NEVER throws; if SMTP_HOST/USER/PASSWORD aren't
         configured, logs a warning and skips sending instead of failing the
         job (attendance still gets marked in the DB either way)
